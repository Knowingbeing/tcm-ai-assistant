## 保存问诊失败根因排查 — 错误透传 + 诊断面板（2026-06-27）
- **根因**：`save_record` 失败时只返回 `False`，UI 只显示「云端保存失败」，用户无法看到实际原因
- **核心修改**：
  1. `save_record` 返回类型从 `bool` 改为 `tuple[bool, str]`，str 携带格式化错误详情
  2. 新增 `_format_supabase_error()` 把 PostgREST 异常翻译为中文排查建议（RLS / NOT NULL / CHECK / 列不存在 / Key 无效 / 网络）
  3. 新增 `diagnose_connection()` 全链路诊断：配置→连接→表存在→列完整→测试写入→清理
  4. 系统设置 Tab 新增「🔍 诊断 Supabase 连接」按钮，输出结构化报告
  5. 保存失败时展开排查建议面板（5 种常见原因 + 对应 SQL）
  6. `get_records / get_sessions / get_session_history` 加排序字段降级容错（created_at→id→无排序）
  7. `save_record` 数据清洗：confidence 截断 0-100、chief_complaint NOT NULL 兜底
  8. `has_api_key` 第①路改为 `.get()` 容错
  9. 数据分析 Tab 顶部显示存储后端 + 记录条数
- commit: e94b3a9
- **常见失败原因排序**（按概率）：
  1. RLS 未关闭（Supabase 新建表默认开 RLS，anon key 无法写入）
  2. 表未创建（只配了 secrets.toml 但没跑 schema.sql）
  3. 缺字段（跑了 schema.sql 但没跑 migration_p1_session.sql）
  4. CHECK 约束（confidence 超出 0-100、gender 不在允许范围）
  5. NOT NULL（chief_complaint 为空）
  6. Key 无效 / 网络不通
