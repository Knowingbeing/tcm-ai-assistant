## Bugfix · API Key 显示非同时性 (2026-06-26)
### 用户反馈
"所有与 API Key 相关的显示都应该在我输入 API Key 之后有一个同时的交互性变化"
— 设置页输入 key 后，Hero 区/状态卡不立即更新，存在明显延迟或不同步

### 根因
1. `get_engine()` 每次 rerun 都重新构建 engine（依赖 LLM 网络探测），网络慢时 `has_api_key` 短暂为 False → UI 闪烁
2. 设置页状态卡读的是函数顶部 `settings = load_settings()` 磁盘快照，`provider`/`model` 显示与当前 selectbox 值不一致
3. DeepSeek 提示读 `current_key`（磁盘值）而非当前输入框值

### 修复
- **新增 `st.session_state._api_key_ok` 标志位**：`get_engine()` 里 key 格式有效（非空且≥10字符）就置 True，不依赖网络探测
- **`main()` Hero 区**：`has_api_key = st.session_state._api_key_ok`，保存后立即同步，不闪烁
- **设置页重构**：
  * API Key 输入框下方实时显示"✅ 格式有效" / "⚠️ 请填写"（读当前 widget 值）
  * 系统状态卡显示 `provider`/`model`（当前 selectbox 值），而非 `settings.get()` 磁盘快照
  * DeepSeek 格式提示用当前 `api_key` 输入值判断
  * 保存成功同时写 `st.session_state._api_key_ok = True`
  * 清除配置同时写 `st.session_state._api_key_ok = False`
- **`main()` 里删掉多余的 `model_name` 重赋值**，避免覆盖 line 594-596 的逻辑
- smoke_test 11 段全过, AST 语法 OK
