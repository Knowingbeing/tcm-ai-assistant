### 1.5 数据质量说明

- **数据来源**：方剂/证型/中药数据均整理自中医经典教材（《伤寒论》《方剂学》《中药学》《中医诊断学》等）

- **已知问题**：`HERBS` 列表中板蓝根条目存在重复 key（`{"name": "板蓝根", "name": "板蓝根", ...}`），Python 字典会取最后一个值，不影响功能但应修复

## 2. 十问歌表单定义 (data/ten_asks.py)

> 文件：150 行 | 核心常量：TEN_ASKS / MENSTRUATION_ASK / TONGUE_ASK / PULSE_ASK / ALL_ASKS / DEFAULT_TEN_ASKS

### 2.1 设计理念

基于中医传统"十问歌"（一问寒热二问汗，三问头身四问便，五问饮食六问腹，七聋八渴俱当辨，九问旧病十问因），将问诊信息采集结构化为 10 个维度 + 3 个扩展维度（经期/舌诊/脉诊）。

### 2.2 TEN_ASKS 列表（10 维度）

每个维度的数据结构：
```python
{
    "key": "cold_heat",          # 存储 key（写入 session_state["ten_asks_data"]）
    "label": "寒热",             # UI 显示标签
    "icon": "🌡️",              # 图标
    "question": "您的寒热情况如何？",  # 问诊问题
    "options": [                 # 选项列表
        "无异常",
        "恶寒发热",
        "但热不寒",
        "但寒不热",
        "寒热往来"
    ],
    "stage": 1,                  # 问诊阶段（1-3，控制展开顺序）
    "sub_asks": [...],           # 可选：子问题（条件展开）
    "multi": False               # 可选：是否多选
}
```

10 个维度详情：

| 序号 | key | label | 选项数 | 子问题 | 说明 |
|------|-----|-------|--------|--------|------|
| 1 | `cold_heat` | 寒热 | 5 | 有（恶寒类型/发热类型） | 寒热是辨别表里寒热的重要依据 |
| 2 | `sweat` | 汗 | 5 | 无 | 汗出与否辨别表虚表实 |
| 3 | `head_body` | 头身 | 6 | 有（头痛部位/身痛类型） | 头身疼痛辨别病位 |
| 4 | `bowel_urine` | 二便 | 6 | 无 | 二便辨别寒热虚实 |
| 5 | `diet_taste` | 饮食口味 | 6 | 有（口渴/口味异常） | 饮食辨别脾胃状况 |
| 6 | `chest_abdomen` | 胸腹 | 5 | 无 | 胸腹症状辨别脏腑病位 |
| 7 | `ear_eye` | 耳目 | 5 | 无 | 耳目辨别肝肾状况 |
| 8 | `sleep` | 睡眠 | 5 | 无 | 睡眠辨别心神状况 |
| 9 | `old_illness` | 旧病 | 4 | 无 | 既往病史 |
| 10 | `cause` | 病因 | 5 | 无 | 发病诱因 |

### 2.6 十问歌与 AI 引擎的数据流

```
用户在 UI 选择十问歌选项
        │
        ▼
写入 sess["ten_asks_data"]["cold_heat"] = "恶寒发热"
写入 sess["ten_asks_data"]["sweat"] = "无汗"
...
        │
        ▼
_collect_symptoms_from_ten_asks(sess)
读取 sess["ten_asks_data"]，遍历所有维度
过滤掉 "无异常"/"正常"/"未填写" 的值
生成症状描述列表：["cold_heat: 恶寒发热", "sweat: 无汗", ...]
        │
        ▼
合并到 sess["symptoms"] 列表
        │
        ▼
传递给 engine.analyze_symptoms(chief, symptoms, tongue, pulse)
        │
        ▼
LLM system prompt 中包含患者完整信息
```

### 2.7 与追问机制的协作

当 `should_ask_followup()` 检测到舌象或脉象为空时，会生成追问问题。用户回答后，`_apply_followup_answer()` 将答案写入 `sess["tongue_sign"]` 或 `sess["pulse_sign"]`（而非 `sess["ten_asks_data"]`）。这是因为舌象和脉象在 session_state 中有独立的 key，便于直接传递给 `analyze_symptoms()` 函数。
