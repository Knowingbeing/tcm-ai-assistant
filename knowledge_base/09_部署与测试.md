# 部署与测试

## 1. 本地开发环境

### 1.1 依赖安装

```bash
# 克隆项目
git clone <repo-url>
cd 中医AI智能问诊助手

# 创建虚拟环境
python -m venv venv
source venv/bin/activate  # Linux/Mac
# 或
venv\Scripts\activate  # Windows

# 安装依赖
pip install -r requirements.txt
```

**requirements.txt 内容**：
```
streamlit>=1.30.0
pandas>=2.1.0
plotly>=5.18.0
numpy>=1.24.0
openai>=1.0.0
python-dotenv>=1.0.0
supabase>=2.0.0
```

### 1.2 配置文件

#### 方式一：.env 文件（本地开发）

```bash
# 复制模板
cp .env.example .env

# 编辑 .env
SUPABASE_URL=https://your-project-ref.supabase.co
SUPABASE_KEY=your-anon-or-service-role-key
```

#### 方式二：.streamlit/secrets.toml（推荐）

```bash
# 复制模板
cp .streamlit/secrets.toml.example .streamlit/secrets.toml

# 编辑 secrets.toml
SUPABASE_URL = "https://your-project-ref.supabase.co"
SUPABASE_KEY = "your-anon-or-service-role-key"
```

**优先级**：`secrets.toml` > 环境变量 > 未配置

### 1.3 启动应用

```bash
# 方式一：直接运行 app.py
streamlit run app.py

# 方式二：通过 streamlit_app.py（Streamlit Cloud 兼容入口）
streamlit run streamlit_app.py
```

应用默认运行在 `http://localhost:8501`。

## 2. Streamlit Cloud 部署

### 2.1 部署步骤

1. 将代码推送到 GitHub 仓库
2. 登录 [share.streamlit.io](https://share.streamlit.io)
3. 选择仓库 → 指定主文件为 `streamlit_app.py`
4. 在 Secrets 中配置 `SUPABASE_URL` 和 `SUPABASE_KEY`
5. 部署

### 2.2 Streamlit Cloud 注意事项

- **临时文件**：`/tmp` 目录可写，JSON 兜底文件存储在 `/tmp/tcm_records.json`
- **配置**：`.streamlit/config.toml` 已设置 `headless=true`、`enableCORS=false`
- **资源限制**：免费版限制 1GB 内存，应用闲置后自动休眠

### 2.3 config.toml 配置

```toml
[theme]
primaryColor = "#0F7A6A"        # 中医青绿主色
backgroundColor = "#FAF8F3"      # 米白背景
secondaryBackgroundColor = "#FFFFFF"  # 卡片白底
textColor = "#1F2933"           # 深灰文字
font = "sans serif"

[server]
headless = true                  # 无浏览器自动打开
enableCORS = false               # Streamlit Cloud 需关闭
enableXsrfProtection = false     # 简化部署

[browser]
gatherUsageStats = false         # 不收集使用统计
```

## 3. Docker 部署

### 3.1 Dockerfile

项目包含 `Dockerfile`，支持容器化部署：

```bash
# 构建镜像
docker build -t tcm-ai-assistant .

# 运行容器
docker run -p 8501:8501 \
  -e SUPABASE_URL=https://your-project.supabase.co \
  -e SUPABASE_KEY=your-key \
  tcm-ai-assistant
```

### 3.2 Docker 部署优势

- 环境隔离：避免依赖冲突
- 可重现：任何环境运行一致
- 易扩展：配合 docker-compose 可快速部署多实例

## 6. 环境变量参考

| 变量名 | 必填 | 说明 | 配置位置 |
|--------|------|------|----------|
| `SUPABASE_URL` | 是 | Supabase 项目 URL | secrets.toml / .env / 环境变量 |
| `SUPABASE_KEY` | 是 | Supabase anon key | secrets.toml / .env / 环境变量 |
| API Key | 否 | LLM API Key | 设置 Tab（存入 settings 表 / 本地文件） |

**注意**：API Key 不通过环境变量配置，而是通过 UI 设置 Tab 输入，存储在 Supabase `settings` 表（加密由 Supabase 连接保障）或本地 JSON 文件中。

## 7. 常见问题排查

### Q1: 保存记录失败 "数据库表不存在"

**原因**：Supabase 中未执行 `schema.sql`
**解决**：在 Supabase SQL Editor 中执行 `supabase/schema.sql`

### Q2: 保存记录失败 "数据库缺少字段：session_id"

**原因**：未执行 P1 迁移脚本
**解决**：在 Supabase SQL Editor 中执行 `supabase/migration_p1_session.sql`

### Q3: AI 辨证返回 "API Key 无效"

**原因**：API Key 未配置或已过期
**解决**：设置 Tab → 输入正确 API Key → 验证 → 保存

### Q4: 数据分析 Tab 无数据

**原因**：缓存未失效或存储后端切换
**解决**：点击数据分析 Tab 的"刷新数据"按钮

### Q5: 十问歌填写后辨证结果未体现

**原因**：早期版本的症状丢失 Bug
**解决**：确认 `_collect_symptoms_from_ten_asks()` 使用 `sess.get("ten_asks_data", {})`（已修复）

### Q6: Supabase 诊断面板显示 "RLS 阻止操作"

**原因**：Supabase 项目启用了 RLS 但未添加 policy
**解决**：执行 `schema.sql` 中的 `disable row level security` 语句，或添加允许 anon 角色的 policy

## 8. 备份与恢复

### 8.1 数据备份

```bash
# 导出 Supabase 数据（通过 SQL Editor）
# SELECT * FROM consultations ORDER BY id;
# 导出为 CSV

# 或使用 JSON 兜底文件
cp /tmp/tcm_records.json backup/tcm_records_$(date +%Y%m%d).json
```

### 8.2 数据恢复

```bash
# 从 JSON 恢复到 Supabase
python scripts/migrate_json_to_supabase.py
```

### 8.3 清空数据

⚠️ **危险操作**：通过设置 Tab 的"清空所有记录"按钮，或执行：
```python
supabase_client.clear_records()  # DELETE FROM consultations WHERE id > 0
```
