# 错误处理与诊断

## 1. 错误处理体系总览

系统在三个层面实现了错误处理，确保任意环节失败都能优雅降级：

```
┌─────────────────────────────────────────────┐
│              用户交互层                       │
│  • 错误提示卡片 (st.error)                   │
│  • 诊断面板 (可视化检测结果)                  │
│  • 操作确认/警告                              │
├─────────────────────────────────────────────┤
│              业务逻辑层                       │
│  • tuple[bool, str] 错误透传                  │
│  • _format_supabase_error() 中文翻译          │
│  • LLM 失败自动降级规则引擎                   │
│  • JSON 解析失败自动降级                      │
├─────────────────────────────────────────────┤
│              基础设施层                       │
│  • Supabase 连接异常捕获                      │
│  • 网络超时处理                               │
│  • 单例客户端重建                              │
│  • JSON 文件读写异常处理                      │
└─────────────────────────────────────────────┘
```

## 2. 存储层错误处理

### 2.1 save_record 错误透传机制

**设计变更历史**：

| 版本 | 返回类型 | 问题 |
|------|----------|------|
| v2.0 初版 | `bool` | 失败时只返回 `False`，无错误信息，用户无法排查 |
| v2.0 修复 | `tuple[bool, str]` | 成功返回 `(True, "")`，失败返回 `(False, "中文错误提示")` |

**当前实现**：
```python
# supabase_client.py
def save_record(record: dict) -> tuple[bool, str]:
    client = get_client()
    if client is None:
        return False, "Supabase 未配置"
    
    cleaned = _clean_record(record)
    try:
        resp = client.table("consultations").insert(cleaned).execute()
        if resp.data:
            return True, ""
        return False, "保存失败：服务器未返回数据"
    except Exception as e:
        msg = _format_supabase_error(e)
        return False, msg

# app.py
def _sb_save_record(record):
    ok, msg = supabase_client.save_record(record)
    if ok:
        load_records.clear()
        return True, ""
    return False, msg  # ← 错误信息透传到 UI

# UI 层
ok, msg = _sb_save_record(record)
if ok:
    st.success("保存成功！")
else:
    st.error(f"保存失败：{msg}")  # ← 直接展示中文错误提示
```

### 2.2 _format_supabase_error 错误翻译表

| 异常特征（字符串匹配） | 翻译结果 | 排查建议 |
|------------------------|----------|----------|
| `row level security` / `rls` | 数据库行级安全策略阻止了操作 | 检查 RLS 配置或使用 service_role key |
| `not-null` / `violates not-null` | 必填字段为空：{col} | 检查数据完整性 |
| `check constraint` / `violates check` | 数据不符合约束条件 | confidence 超出 0-100，或 source 值不合法 |
| `column` + `does not exist` | 数据库缺少字段：{col} | 执行 migration_p1_session.sql |
| `relation` + `does not exist` | 数据库表不存在 | 执行 schema.sql 建表脚本 |
| `invalid api key` / `401` | Supabase API Key 无效 | 检查 secrets.toml 中的 SUPABASE_KEY |
| `connection` / `timeout` / `dns` | 网络连接失败 | 检查网络或 Supabase 服务状态 |
| 其他 | 保存失败：{原始错误} | 查看详细错误信息 |

### 2.3 降级保存策略

```
save_record() 调用
       │
       ▼
  Supabase 可用？
       │
   ┌───┴───┐
  Yes      No
   │       │
   ▼       ▼
 insert   返回 (False, "Supabase 未配置")
   │           │
 成功?         ▼
   │       app.py 降级到 JSON
 ┌─┴─┐     _save_to_json(records)
 Yes   No      │
 │     │       ▼
 │     ▼    返回 (True, "")
 │  _format_supabase_error()
 │     │
 │     ▼
 │  返回 (False, msg)
 │     │
 │     ▼
 │  app.py 降级到 JSON
 │  _save_to_json(records)
 │     │
 │     ▼
 │  返回 (True, "")  ← 即使 Supabase 失败，JSON 兜底成功
 │
 ▼
 返回 (True, "")
```

## 3. AI 引擎错误处理

### 3.1 LLM 调用错误分类

```python
# llm_engine.py analyze_symptoms() 中的错误处理

try:
    resp = self.client.chat.completions.create(...)
    content = resp.choices[0].message.content.strip()
    result = json.loads(content)
    return result
    
except json.JSONDecodeError:
    # LLM 返回非 JSON 格式 → 降级规则引擎
    return self._rule_based_diagnosis(...)
    
except Exception as e:
    err = str(e).lower()
    
    if "401" in err or "invalid api key" in err:
        # API Key 无效
        return self._error_result("API Key 无效，请检查设置")
    
    if "404" in err or "model" in err:
        # 模型不存在
        return self._error_result(f"模型 {self.model} 不可用")
    
    if "429" in err or "rate limit" in err:
        # 频率限制
        return self._error_result("请求频率超限，请稍后重试")
    
    # 网络错误或其他 → 降级规则引擎
    return self._rule_based_diagnosis(...)
```

### 3.2 降级策略表

| 错误类型 | 处理方式 | 用户感知 | 严重程度 |
|----------|----------|----------|----------|
| API Key 无效 | 返回错误提示 | 看到"API Key 无效" | ⚠️ 中 |
| 模型不存在 | 返回错误提示 | 看到"模型不可用" | ⚠️ 中 |
| 频率限制 | 返回错误提示 | 看到"请稍后重试" | ⚠️ 低 |
| JSON 解析失败 | 静默降级规则引擎 | 获得规则引擎结果（可能不太准确） | ℹ️ 低 |
| 网络错误 | 静默降级规则引擎 | 获得规则引擎结果 | ℹ️ 低 |
| 未知错误 | 静默降级规则引擎 | 获得规则引擎结果 | ℹ️ 低 |

### 3.3 _error_result 辅助函数

```python
def _error_result(self, msg: str) -> dict:
    """构造错误结果 dict，保持与正常结果相同的结构"""
    return {
        "syndrome": "辨证失败",
        "syndrome_category": "待分类",
        "analysis": f"AI 辨证失败：{msg}。建议检查 API Key 配置。",
        "formula": "待推荐",
        "formula_adjustment": "",
        "treatment_principle": "",
        "confidence": 0
    }
```

## 4. Supabase 全链路诊断面板

### 4.1 诊断流程

```
用户点击 [运行诊断]
       │
       ▼
  diagnose_connection()
       │
       ├─ Step 1: 配置检测
       │  └─ _get_credentials() → URL + Key 是否存在？
       │
       ├─ Step 2: 连接测试
       │  └─ get_client() → create_client(url, key) 是否成功？
       │
       ├─ Step 3: 表存在性
       │  └─ client.table("consultations").select("*").limit(1).execute()
       │     是否报 "relation does not exist"？
       │
       ├─ Step 4: 列完整性
       │  └─ 检查返回数据的字段是否包含所有 required_columns
       │     (20 个必需字段)
       │
       ├─ Step 5: 测试写入
       │  └─ insert 一条 chief_complaint="__DIAG_TEST__" 的测试记录
       │
       └─ Step 6: 清理
          └─ delete 测试记录 (WHERE chief_complaint='__DIAG_TEST__')
```

### 4.2 诊断结果展示

每个步骤的结果以卡片形式展示：

```
┌─────────────────────────────────────────┐
│  ✅ 配置检测                             │
│  URL + Key 已配置                        │
├─────────────────────────────────────────┤
│  ✅ 连接测试                             │
│  连接成功                                │
├─────────────────────────────────────────┤
│  ❌ 表存在性                             │
│  查询失败: 数据库表不存在，请执行         │
│  supabase/schema.sql 建表脚本            │
├─────────────────────────────────────────┤
│  ⏭️ 列完整性 (跳过)                      │
│  依赖前序步骤成功                        │
├─────────────────────────────────────────┤
│  ⏭️ 测试写入 (跳过)                      │
│  依赖前序步骤成功                        │
├─────────────────────────────────────────┤
│  ⏭️ 清理 (跳过)                          │
│  依赖前序步骤成功                        │
└─────────────────────────────────────────┘
诊断结果：4/6 步骤通过，2 步骤失败
```

**短路逻辑**：前序步骤失败时，后续步骤标记为"跳过"，避免连锁错误。

## 5. 已修复的 Bug 记录

### 5.1 症状丢失 Bug

| 项目 | 内容 |
|------|------|
| **症状** | 十问歌表单中选择的症状信息未传递给 AI 引擎 |
| **根因** | `app.py` 中 `_collect_symptoms_from_ten_asks()` 使用 `sess.get("ten_asks", {})` 读取数据，但实际存储 key 为 `"ten_asks_data"` |
| **影响** | 十问歌 10 个维度的信息全部丢失，AI 只收到主诉和手动选择的症状标签 |
| **修复** | `sess.get("ten_asks", {})` → `sess.get("ten_asks_data", {})` |
| **文件** | `app.py` `_collect_symptoms_from_ten_asks()` 函数 |

### 5.2 save_record 错误吞没 Bug

| 项目 | 内容 |
|------|------|
| **症状** | 保存问诊记录失败时，用户只看到"保存失败"，无法知道原因 |
| **根因** | `save_record()` 返回 `bool`，吞没了所有异常信息 |
| **影响** | 用户无法自行排查 Supabase 连接问题 |
| **修复** | 返回类型改为 `tuple[bool, str]`，通过 `_format_supabase_error()` 翻译异常 |
| **文件** | `supabase_client.py` `save_record()` + `app.py` `_sb_save_record()` |

### 5.3 get_records 排序崩溃 Bug

| 项目 | 内容 |
|------|------|
| **症状** | 多条记录在同一秒保存时，列表顺序不确定，偶尔出现排序异常 |
| **根因** | 仅按 `created_at DESC` 排序，时间戳相同时 Supabase 返回顺序不确定 |
| **影响** | 数据分析 Tab 中记录列表顺序跳动 |
| **修复** | 添加 `id DESC` 作为降级排序：`.order("created_at", desc=True).order("id", desc=True)` |
| **文件** | `supabase_client.py` `get_records()` |

### 5.4 has_api_key KeyError Bug

| 项目 | 内容 |
|------|------|
| **症状** | 首次加载页面时偶发 `KeyError: '_api_key_ok'` |
| **根因** | 四路判定中第一路 `st.session_state["_api_key_ok"]` 直接索引访问，key 不存在时抛异常 |
| **影响** | 页面加载失败，用户需刷新 |
| **修复** | 改为 `st.session_state.get("_api_key_ok", False)` 安全访问 |
| **文件** | `app.py` `has_api_key()` 函数 |

## 6. 错误预防措施

### 6.1 数据清洗 (_clean_record)

在写入 Supabase 前对所有字段进行清洗，防止约束违反：

```python
def _clean_record(record: dict) -> dict:
    return {
        "chief_complaint": record.get("chief_complaint", "未填写"),  # NOT NULL
        "confidence": max(0, min(100, record.get("confidence", 0))),  # CHECK [0,100]
        "source": record.get("source", "manual"),  # CHECK enum
        "symptoms": record.get("symptoms", []),  # jsonb default []
        "messages": record.get("messages", []),  # jsonb default []
        # ... 其他字段默认空字符串
    }
```

### 6.2 JSON 响应解析保护

```python
# 清理 markdown 代码块标记
content = resp.choices[0].message.content.strip()
if content.startswith("```"):
    content = content.split("\n", 1)[-1].rsplit("```", 1)[0].strip()

# JSON 解析失败时降级
try:
    result = json.loads(content)
except json.JSONDecodeError:
    return self._rule_based_diagnosis(...)

# 字段默认值保护
result.setdefault("syndrome", "待辨证")
result.setdefault("confidence", 60)
```
