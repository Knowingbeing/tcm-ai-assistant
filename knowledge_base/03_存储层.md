## 1. 存储架构总览

系统采用**双存储后端**设计，运行时自动切换：

```
                ┌──────────────────────┐
                │  app.py (调用方)      │
                └──────────┬───────────┘
                           │
                ┌──────────▼───────────┐
                │ supabase_client      │
                │ .is_configured()     │
                └───┬──────────────┬───┘
                    │              │
              True  │          False│
                    ▼              ▼
           ┌────────────┐   ┌────────────┐
           │ Supabase   │   │ JSON 文件   │
           │ PostgreSQL │   │ /tmp/ 或   │
           │ (云端)     │   │ data/      │
           └────────────┘   └────────────┘
```

### 1.1 存储后端选择逻辑

```python
# supabase_client.py
def is_configured() -> bool:
    """快速判断 Supabase 是否已配置"""
    url, key = _get_credentials()
    return bool(url and key)
```

- 返回 `True` → 使用 Supabase（云端优先）
- 返回 `False` → 使用 JSON 文件（本地兜底）

### 1.2 凭证获取优先级

```python
def _get_credentials() -> tuple[str | None, str | None]:
    """
    凭证来源优先级：
    1. st.secrets (Streamlit secrets.toml)  ← 部署环境
    2. 环境变量 SUPABASE_URL / SUPABASE_KEY  ← 本地 .env
    3. 返回 (None, None)  ← 未配置
    """
    # ① st.secrets
    try:
        import streamlit as st
        url = st.secrets.get("SUPABASE_URL")
        key = st.secrets.get("SUPABASE_KEY")
        if url and key:
            return url, key
    except Exception:
        pass
    
    # ② 环境变量
    url = os.environ.get("SUPABASE_URL")
    key = os.environ.get("SUPABASE_KEY")
    if url and key:
        return url, key
    
    # ③ 未配置
    return None, None
```

### 2.1 客户端单例模式

```python
_CLIENT = None  # 模块级全局变量

def get_client():
    """
    单例模式获取 Supabase 客户端。
    未配置时返回 None。
    """
    global _CLIENT
    if _CLIENT is not None:
        return _CLIENT
    
    url, key = _get_credentials()
    if not url or not key:
        return None
    
    try:
        from supabase import create_client
        _CLIENT = create_client(url, key)
        return _CLIENT
    except Exception as e:
        print(f"[Supabase] 客户端创建失败: {e}")
        return None
```

**设计要点**：
- 模块级 `_CLIENT` 全局变量，避免重复创建连接
- 创建失败返回 `None`，不抛异常，让调用方优雅降级
- `is_configured()` 只检查凭证是否存在，`get_client()` 才真正创建连接

### 2.2 数据读取

#### `get_records()` — 获取全部问诊记录

```python
def get_records() -> list[dict]:
    """
    从 consultations 表读取所有记录。
    排序：created_at DESC → id DESC（双重排序保证稳定性）
    """
    client = get_client()
    if client is None:
        return []
    
    try:
        resp = (client
                .table("consultations")
                .select("*")
                .order("created_at", desc=True)
                .order("id", desc=True)
                .execute())
        return resp.data if resp.data else []
    except Exception as e:
        print(f"[Supabase] get_records 失败: {e}")
        return []  # 返回空列表，不抛异常
```

**排序设计**：`created_at DESC` + `id DESC` 双重排序。当多条记录的 `created_at` 相同时（同一秒内保存），`id DESC` 确保最新插入的排在前面。

**Bug 修复记录**：早期版本仅按 `created_at` 排序，当时间戳完全相同时 Supabase 返回顺序不确定，导致列表顺序跳动。添加 `id DESC` 降级排序后稳定。

                .order("created_at", desc=True)
                .order("id", desc=True)

        # 按 session_id 分组，取每组第一条

        for row in resp.data:
            sid = row.get("session_id", "")

                sessions[sid] = row
        return list(sessions.values())
    except Exception:
        return []

### 2.3 数据写入

#### `save_record(record) -> tuple[bool, str]` — 保存单条记录

```python
def save_record(record: dict) -> tuple[bool, str]:
    """
    保存一条问诊记录到 Supabase。
    
    返回：(成功?, 错误信息)
    - 成功：(True, "")
    - 失败：(False, "中文错误提示")
    
    失败时会自动降级到 JSON 文件保存。
    """
    client = get_client()
    if client is None:
        return False, "Supabase 未配置"
    
    # 数据清洗
    cleaned = _clean_record(record)
    
    try:
        resp = client.table("consultations").insert(cleaned).execute()
        if resp.data:
            return True, ""
        return False, "保存失败：服务器未返回数据"
    except Exception as e:
        msg = _format_supabase_error(e)
        return False, msg
```

#### `_clean_record(record)` — 数据清洗

```python
def _clean_record(record: dict) -> dict:
    """
    清洗记录数据，确保符合 schema 约束：
    - chief_complaint 不能为空 (NOT NULL)
    - confidence ∈ [0, 100] (CHECK 约束)
    - source ∈ ('manual', 'api', 'imported', 'chat', 'draft') (CHECK 约束)
    - symptoms 必须是 JSON 数组
    - messages 必须是 JSON 数组
    - 字符串字段默认空字符串
    """
    cleaned = {
        "name": record.get("name", "匿名"),
        "age": record.get("age", 0),
        "gender": record.get("gender", ""),
        "chief_complaint": record.get("chief_complaint", "未填写"),
        "symptoms": record.get("symptoms", []),
        "tongue_sign": record.get("tongue_sign", ""),
        "pulse_sign": record.get("pulse_sign", ""),
        "syndrome": record.get("syndrome", "待辨证"),
        "syndrome_category": record.get("syndrome_category", "待分类"),
        "formula": record.get("formula", "待推荐"),
        "formula_adjustment": record.get("formula_adjustment", ""),
        "treatment_principle": record.get("treatment_principle", ""),
        "analysis": record.get("analysis", ""),
        "confidence": max(0, min(100, record.get("confidence", 0))),
        "source": record.get("source", "manual"),
        "session_id": record.get("session_id", ""),
        "round_index": record.get("round_index", 0),
        "messages": record.get("messages", []),
    }
    return cleaned
```

**Bug 修复记录**：早期版本 `save_record` 吞没所有异常，只返回 `False` 不提供错误信息，用户无法排查。改为返回 `tuple[bool, str]` 后，错误信息直接展示在 UI 上。

### 2.4 错误翻译

#### `_format_supabase_error(e)` — Supabase 异常翻译为中文提示

```python
def _format_supabase_error(e: Exception) -> str:
    """
    将 Supabase/PostgreSQL 异常翻译为用户可理解的中文提示。
    """
    err_str = str(e).lower()
    
    # RLS 权限错误
    if "row level security" in err_str or "rls" in err_str:
        return "数据库行级安全策略阻止了操作，请检查 RLS 配置或使用 service_role key"
    
    # NOT NULL 约束
    if "not-null" in err_str or "violates not-null" in err_str:
        col = _extract_column_name(err_str)
        return f"必填字段为空：{col}，请检查数据完整性"
    
    # CHECK 约束
    if "check constraint" in err_str or "violates check" in err_str:
        return f"数据不符合约束条件（如 confidence 超出 0-100 范围，或 source 值不合法）"
    
    # 列不存在
    if "column" in err_str and "does not exist" in err_str:
        col = _extract_column_name(err_str)
        return f"数据库缺少字段：{col}，请执行 supabase/migration_p1_session.sql 迁移脚本"
    
    # 表不存在
    if "relation" in err_str and "does not exist" in err_str:
        return "数据库表不存在，请执行 supabase/schema.sql 建表脚本"
    
    # API Key 无效
    if "invalid api key" in err_str or "401" in err_str:
        return "Supabase API Key 无效，请检查 .streamlit/secrets.toml 中的 SUPABASE_KEY"
    
    # 网络错误
    if "connection" in err_str or "timeout" in err_str or "dns" in err_str:
        return "网络连接失败，请检查网络或 Supabase 服务状态"
    
    # 通用错误
    return f"保存失败：{str(e)}"
```

### 2.5 全链路诊断

#### `diagnose_connection() -> dict` — Supabase 连接诊断

```python
def diagnose_connection() -> dict:
    """
    全链路诊断 Supabase 连接状态。
    
    检测步骤（顺序执行）：
    1. 配置检测：URL + Key 是否已配置
    2. 连接测试：能否创建客户端并连接
    3. 表存在性：consultations 表是否存在
    4. 列完整性：consultations 表是否有所有必需字段
    5. 测试写入：插入一条测试记录
    6. 清理：删除测试记录
    
    返回 dict:
    {
        "steps": [
            {"name": "配置检测", "ok": True, "detail": "URL + Key 已配置"},
            {"name": "连接测试", "ok": True, "detail": "连接成功 (120ms)"},
            ...
        ],
        "all_ok": True/False,
        "error_count": 0
    }
    """
    steps = []
    
    # Step 1: 配置检测
    url, key = _get_credentials()
    steps.append({
        "name": "配置检测",
        "ok": bool(url and key),
        "detail": "URL + Key 已配置" if url and key else "未配置 SUPABASE_URL 或 SUPABASE_KEY"
    })
    if not (url and key):
        return {"steps": steps, "all_ok": False, "error_count": 1}
    
    # Step 2: 连接测试
    client = get_client()
    steps.append({
        "name": "连接测试",
        "ok": client is not None,
        "detail": "连接成功" if client else "客户端创建失败"
    })
    if client is None:
        return {"steps": steps, "all_ok": False, "error_count": 1}
    
    # Step 3: 表存在性
    required_columns = [
        "id", "name", "age", "gender", "chief_complaint",
        "symptoms", "tongue_sign", "pulse_sign",
        "syndrome", "syndrome_category", "formula",
        "formula_adjustment", "treatment_principle",
        "analysis", "confidence", "source",
        "session_id", "round_index", "messages",
        "created_at"
    ]
    
    try:
        # 尝试查询一条记录来检测表和列
        resp = client.table("consultations").select("*").limit(1).execute()
        steps.append({
            "name": "表存在性",
            "ok": True,
            "detail": "consultations 表存在"
        })
    except Exception as e:
        steps.append({
            "name": "表存在性",
            "ok": False,
            "detail": f"查询失败: {_format_supabase_error(e)}"
        })
        return {"steps": steps, "all_ok": False, "error_count": sum(1 for s in steps if not s["ok"])}
    
    # Step 4: 列完整性（通过返回的字段判断）
    if resp.data:
        existing_cols = set(resp.data[0].keys())
        missing = set(required_columns) - existing_cols
    else:
        # 表为空时无法通过数据判断列，使用 RPC 或信任 schema
        missing = set()
    
    steps.append({
        "name": "列完整性",
        "ok": len(missing) == 0,
        "detail": f"{len(required_columns) - len(missing)}/{len(required_columns)} 列完整" 
                  + (f"，缺失: {missing}" if missing else "")
    })
    
    # Step 5: 测试写入
    test_record = {
        "name": "诊断测试",
        "age": 0,
        "gender": "",
        "chief_complaint": "__DIAG_TEST__",
        "symptoms": [],
        "source": "draft",
        "confidence": 0,
    }
    test_id = None
    try:
        resp = client.table("consultations").insert(test_record).execute()
        test_id = resp.data[0]["id"] if resp.data else None
        steps.append({
            "name": "测试写入",
            "ok": True,
            "detail": "成功写入测试记录"
        })
    except Exception as e:
        steps.append({
            "name": "测试写入",
            "ok": False,
            "detail": _format_supabase_error(e)
        })
    
    # Step 6: 清理
    if test_id:
        try:
            client.table("consultations").delete().eq("id", test_id).execute()
            steps.append({"name": "清理", "ok": True, "detail": "已删除测试记录"})
        except Exception:
            steps.append({"name": "清理", "ok": False, "detail": "测试记录删除失败（不影响使用）"})
    
    error_count = sum(1 for s in steps if not s["ok"])
    return {
        "steps": steps,
        "all_ok": error_count == 0,
        "error_count": error_count
    }
```

def get_settings() -> dict:
    """读取 settings 表（单行表，id=1）"""
    client = get_client()
    if client is None:

def save_settings(api_key: str, provider: str, model: str) -> bool:
    """保存设置到 settings 表（upsert）"""
    client = get_client()
    if client is None:
        return False
    
    try:

            "id": 1,
            "api_key": api_key,
            "provider": provider,
            "model": model,
            "updated_at": "now()"

        return True
    except Exception:
        return False

## 3. 遗留 SQLite 模块 (utils/database.py)

### 3.1 历史背景

`database.py` 是 v1.0 时代的本地存储方案，使用 SQLite3 存储中医知识库和问诊记录。v2.0 迁移到 Supabase 后，此模块保留作为参考但不再使用。

### 3.2 表结构（SQLite）

| 表名 | 说明 | 字段数 |
|------|------|--------|
| `patients` | 患者档案 | 6 (patient_id, name, gender, age, constitution, created_at) |
| `syndromes` | 证型库 | 9 (syndrome_id, syndrome_name, category, ...) |
| `formulas` | 方剂库 | 7 (formula_id, formula_name, composition, ...) |
| `symptoms` | 症状库 | 5 (symptom_id, symptom_name, category, ...) |
| `herbs` | 中药库 | 9 (herb_id, herb_name, nature, flavor, ...) |
| `consultations` | 问诊记录 | 11 (含外键关联 syndromes / formulas) |
| `consultation_symptoms` | 问诊-症状关联表 | 3 (多对多) |

### 3.3 与 Supabase schema 的差异

| 对比项 | SQLite (database.py) | Supabase (schema.sql) |
|--------|---------------------|----------------------|
| 问诊记录字段 | 11 个（含外键） | 17 个（扁平化，含 session_id/messages） |
| 证型存储 | 独立 syndromes 表 | 嵌入 consultations.syndrome 文本字段 |
| 方剂存储 | 独立 formulas 表 | 嵌入 consultations.formula 文本字段 |
| 多轮问诊 | 不支持 | 支持（session_id + round_index + messages） |
| 关系完整性 | 外键约束 | 无外键（扁平化设计） |
| 知识库存储 | 数据库表 | 内存常量 (tcm_data.py) |

## 5. 数据迁移工具 (scripts/migrate_json_to_supabase.py)

用于将旧的 JSON 文件数据批量迁移到 Supabase。

**使用场景**：用户从 JSON 模式切换到 Supabase 模式时，运行此脚本将历史数据导入云端。

**工作流程**：
1. 读取 `/tmp/tcm_records.json`（或 `data/tcm_records.json`）
2. 逐条调用 `supabase_client.save_record()` 写入 Supabase
3. 统计成功/失败数量，输出迁移报告
4. 失败记录输出详细错误信息

**安全设计**：迁移不删除原 JSON 文件，用户确认云端数据正确后可手动清理。
